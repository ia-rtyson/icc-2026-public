# YouTrack seed

Two files belong here, both generated by `scripts/youtrack-snapshot.sh` and both
committed:

| File | What it is |
|---|---|
| `youtrack-seed.tar.gz` | The `data` and `conf` volumes of a provisioned YouTrack, ~38 MB raw |
| `token.env` | `YOUTRACK_TOKEN=…` — the permanent token that lives inside that instance |

`services/youtrack/restore.sh` unpacks the tarball into empty volumes on first
boot, so a brand-new environment gets a tracker that already has the UI Issues
project, the Stage field, the board columns, and the API token the gateway's MCP
connection config is encrypted with. `token.env` is loaded by the ignition
service's `env_file` so `exchange.issueReport.pipeline.purgeTickets()` has its credential
without anyone editing `.env`.

If this directory is empty, nothing breaks — YouTrack starts blank and shows its
setup wizard, and the purge job sits at `no_token`. Provision it by hand (see
`.env.example`) and then run the snapshot script so the next person does not
have to.

The tarball contains the YouTrack admin account and a live API token, and
`token.env` carries that token in plaintext. **That is deliberate and accepted**
— this is a throwaway demo tracker holding nothing real, and it is public-safe
by explicit decision. Do not "fix" it by gitignoring either file; that breaks
the only thing they exist for.

⚠️ Snapshot with YouTrack stopped — the script does that for you. A live copy of
an embedded Xodus store is not guaranteed consistent, and a half-written one
restores into an instance that fails later on some unrelated page.
